# AIニュース朝刊（平日の朝のAIニュースまとめ）設計書

作成：2026-11-03

## 目的

平日の朝、AI関連ニュースを要約付きでSlackに届ける。毎日のリアクションで「自分好み」に寄せていく。
まずは個人用。精度が出たら公開版（メルマガ・Threads など）を検討する。

読む目的は4つすべて：
- 開発・仕事にすぐ使う（Bubble などのノーコード開発、Claude Code・MCP の活用）
- 発信ネタを集める
- 業界の流れを把握する
- 技術を深く理解する

## 決めたこと

| 項目 | 内容 |
| --- | --- |
| 配信日 | 月〜金 |
| 届く時刻 | 9:05〜9:20頃（起動は 8:52、日本時間） |
| 対象期間 | 火〜金：前日の 0:00〜23:59（日本時間）。月：金曜 0:00〜日曜 23:59 |
| 分量 | 10件前後＋しっかりした全体分析（読む時間 5〜10分） |
| 配信先 | Slack（ワークスペース Hirokawa）`#ai_news`（親メッセージ＋1件ごとのスレッド返信） |
| 記録 | Nochon「🤖 AIニュース」ページの下（1日1ページ・好みのメモ・各社の動きメモ） |
| 指示書・情報源・収集スクリプト | このリポジトリの `ai-news/` |
| 動かし方 | Claude Code の Routine（毎回新しいセッション） |

※ 月曜の対象に金曜を含めたのは、「前日のみ」だと金曜の記事がどの日にも入らなくなるため。

### 話題の配分

| 話題 | 扱い |
| --- | --- |
| Claude・Anthropic | 最優先 |
| その他のLLM | しっかり |
| MCP・AIエージェント | しっかり |
| 画像・動画・音声の生成AI | しっかり |
| 噂・リーク | 普通。「未確認」と明記 |
| 研究論文 | 普通。実用化の見込みがあるものを優先 |

### 情報源

一次情報（公式ブログ・リリースノート・GitHub リリース・ドキュメント更新）とコミュニティ（Hacker News・Reddit・開発者ブログ）を中心に、英語の大手テックメディアで補う。日本語メディアは日本独自の話題だけ拾う。一覧は `ai-news/SOURCES.md`。

## 構成

```
Routine（平日 8:52 JST、毎回新しいセッション）
  ① Slack #ai_news：前回分のリアクションとスレッドの書き込みを読む
  ② Nochon：好みのメモ・各社の動きメモ・直近7日分を読む → 好みのメモを更新
  ③ 収集スクリプト（ai-news/collect.py：フィード・Hacker News・npm）で日付付きの候補を集め、
     フィードの無い一次情報を開いて確認し、Web検索で補う（20〜30件）
  ④ 公開日を確かめる → 重複をまとめる → 点数を付ける → 10件前後を選ぶ
  ⑤ 要約と全体分析を書く（直近7日分と各社の動きメモを踏まえる）
  ⑥ Slack #ai_news に投稿（親メッセージ＋1件ごとのスレッド返信）
  ⑦ Nochon：その日のページを保存し、各社の動きメモを更新する
```

### 配信の形

- 親メッセージ：見出し（日付・対象期間）、目次、全体分析（傾向・各社の動き・あなたへの示唆）、前回の反応から学んだこと（1行）
- スレッド返信（1件ずつ）：【すぐ試せる／発信ネタ／業界の流れ／深掘り】の印、見出し、要約2〜3行、あなたへの関係、引用元リンク

### 学習の仕組み

| リアクション | 意味 | 反映 |
| --- | --- | --- |
| 👍 | こういうのが欲しい | 似た話題や情報源を優先 |
| 👎 | 要らない | 似た話題を減らす |
| 🔍 | もっと深く知りたい | 続報を追う。スレッドに詳しい解説を返す |

- スレッドへの書き込みも読み取って反映する
- あなたが Nochon の好みのメモに直接書いた内容は最優先で守る

### Nochon の入り口（personal-notes リポジトリ）

`/api/agent/ai-news`（合言葉 `NOCHON_AGENT_TOKEN`、本人は `BLOG_OWNER_EMAILS`）。触れるのは「🤖 AIニュース」ページとその下だけ。

- `GET ?days=7`：好みのメモ・各社の動きメモ・直近の日次ページ
- `PUT {page:"preferences"|"trends", content}`：書き換え
- `PUT {page:"daily", date, content}`：その日のページを保存（同じ日付は上書き）

## 速報（11/5 追加）

- 日本時間 8〜21時台の毎時5分に、GitHub Actions（`.github/workflows/ai-news-breaking.yml`）が `ai-news/breaking.py` を動かす
- 各社のフィード・Anthropic のニュース一覧・Claude Code の新しい版から候補を集め、Nochon の `/api/agent/ai-news-breaking` に送る
- Nochon は「速報の記録」にない記事のうち、時刻の分かるものは90分以内・日付だけのものは今日の分に絞り、Claude（Sonnet 5.5）で判断する
- 速報にするのは「主要なAIツールの新モデル・大きな新機能」と「大きな業界ニュース」だけ（1回最大3件、迷ったら載せない）
- ボット「AI News」が `#ai_news` に「⚡ 速報」のカードで流す。翌朝の配信は速報済みの話題をカードにせず、1行で触れる
- 22時〜翌8時の分は流さず、翌朝の配信に回る

## 個人 Threads への素材（11/5 追加）

- 毎朝の配信のあと、10件から「幅広い人が情報としてありがたいと思える、生活に響くアプリ・機能の話」を1件選び、素材を Nochon の `/api/agent/threads-material` に送る。Nochon が takatoshihirokawa/hirokawa-threads の `materials/ai-news/<日付>-morning.json` に置く
- 速報も、Threads 向きなら1回につき1件、`<日付>-breaking-<HHMM>.json` として置く
- 投稿文は hirokawa-threads 側がルールと口調で書いて投稿する（確認なし、1日2本まで、原文 URL は付けない）。素材の形式は hirokawa-threads の作業ルール 7-7

## 失敗した時

| 状況 | 対応 |
| --- | --- |
| Nochon につながらない | Slack 配信は行い、末尾に「⚠️ Nochonに保存できませんでした」 |
| ニュースが少ない | 無理に増やさず「今日は少なめ」と書く |
| リアクションが読めない | 好みのメモはそのままで配信 |
| 公開日が確認できない記事 | 載せない |

## 確認の方法

1. Nochon の入り口：反映後に実際に読み書きする
2. Routine：本番前に1回手動で動かし、本番と同じ流れを試す
3. 本番：2026-11-04（水）から

## 実装の手順

1. personal-notes に `/api/agent/ai-news` を追加（PR）→ マージ・反映 → 読み書きを確認
2. このリポジトリに `ai-news/INSTRUCTIONS.md`・`ai-news/SOURCES.md` を追加（PR）→ マージ
3. Slack に `#ai_news` を作る（本人）
4. Routine を作成（平日 8:52 JST、Slack 接続付き）→ 手動で1回実行して確認
