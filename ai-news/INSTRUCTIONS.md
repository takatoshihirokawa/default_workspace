設計の背景は `docs/superpowers/specs/2026-11-03-ai-news-digest-design.md`。

このファイルと `ai-news/SOURCES.md` は読むだけ。リポジトリにコミット・プッシュはしない。

### 必ず守ること
- **途中でやめない。** 試し実行でも、必ず手順 7 まで進めて Slack に投稿する。候補が少なくても、見つかった分で配信する。本当に 0 件のときも「対象期間に該当ニュースなし」と1通投稿する（届かないと、動いたかどうか本人にわからないため）
- **ページの取得は WebFetch を使う。** `curl` は 403 などで弾かれやすい。WebFetch でも読めないページは Web 検索で同じ記事を探す
- **Slack の読み取りは `mcp__Slack__*`、投稿は手順 6 の Nochon の入り口（ボット「AI News」）。** Slack のツールが見当たらなければ ToolSearch で `slack` を探して読み込む。それでも無ければ、最後の報告にその旨を書く

## 2. 前回の反応を読み、好みのメモを更新する

1. 配信先はワークスペース「Hirokawa」の `#ai_news`（チャンネル ID：`C0CF9HW549W`）。読み書きはこの ID で行う
2. `slack_read_channel`（`response_format: detailed`、`oldest` は 5日前）で、「📰 AIニュース」で始まる親メッセージのうち、まだ反映していないもの（直近の 1〜2 回分）を探す
3. 親メッセージごとに `slack_read_thread`（`detailed`）でスレッドを読む
   - 配信はボット「AI News」（`bot_id` 付き）が投稿している（投稿に失敗した日だけ本人の名前）。見分けは本文の書き出しで行う
   - 本文（通知用の文章）が `#1 【` のように番号と【で始まる返信 ＝ ニュース1件。付いているリアクションを読む
   - `🔍 解説`・`📊 全体分析`・`📋 その他の見出し` で始まる返信 ＝ あなたが前に書いたもの（反応の対象にしない）
   - `⚡ 速報` で始まる親メッセージ ＝ 日中に流した速報。付いたリアクションとスレッドの書き込みも、ニュース1件と同じように読む
   - それ以外でボット（`bot_id` 付き）の返信 ＝ 本人の質問へのボットの回答。反応の対象にしない
   - それ以外の返信 ＝ 本人の書き込み（質問を含む）。何に興味を持ったかを読み取って好みに反映する。質問が多い話題は「もっと知りたい」と同じ扱いにする
   - 親メッセージへのリアクション・返信も、全体への感想として読む

| リアクション | 反映 |
| --- | --- |
| 👍（`+1`・`thumbsup`） | その話題・情報源・切り口を優先する |
| 👎（`-1`・`thumbsdown`） | その話題・切り口を減らす |
| 🔍（`mag`・`mag_right`） | 続報を追う対象にする。手順 6 でそのスレッドに解説を返す |

4. 好みのメモを更新する。書き方：
   - 冒頭の「本人が書いたこと」欄は、本人が Nochon で直接書いた部分。**書き換えず、最優先で守る**
   - 「学んだこと」欄に、反応から読み取った傾向を短く足す。同じ傾向は1行にまとめ、古くて矛盾するものは消す。全体で 60 行以内に保つ
   - 「追いかけ中」欄に 🔍 が付いた話題を入れる（2週間たったら消す）
   - 最後の行に「最終反映：YYYY-MM-DD の配信分」と書く（同じ配信を二重に反映しないため）

```bash
curl -sS -X PUT "https://personal-notes-khaki.vercel.app/api/agent/ai-news" \
  -H "Content-Type: application/json" \
  --data-binary @/tmp/preferences.json   # {"page":"preferences","content":"..."}
```

JSON は手で書かず、`python3 -c 'import json,sys; ...'` などで作る（改行や引用符の崩れを防ぐ）。

## 4. 選ぶ（10件前後）

1. **公開日を確かめる**：スクリプトで集めた記事は確認済み。それ以外は、記事ページや検索結果に出ている日付を見る。時刻があれば日本時間に直し、日付だけなら「その日付が対象期間の日と同じ」なら対象とする。日付がどこにも見つからないものだけ載せない
2. **前回までと重複させない**：直近7日分の日次ページに載せた話題は外す。ただし大きな続報は「続報」として載せてよい
   - **速報で流したものも重複させない**：`#ai_news` の、前回の配信以降の「⚡ 速報」で始まる投稿（ボット「AI News」が日中に流したもの）を読み、同じ話題は10件のカードにしない。「各社の動き」に「（速報済み）」と付けて1行で触れる
3. **同じ話題はまとめる**：1件にして、リンクは一次情報（公式）を優先。補足に役立つ記事は2本目のリンクにしてよい
4. **点数を付ける**：次の順で重く見る
   - 好みのメモ（本人が書いたこと ＞ 学んだこと）
   - 話題の配分（下の表）
   - 4つの目的のどれかに当たるか：すぐ試せる／発信ネタ／業界の流れ／深掘り
5. **10件前後を選ぶ**。月曜は3日分なので基準を厳しくして同じくらいの件数にする。少ない日は無理に増やさず「今日は少なめ」と書く
6. Claude・Anthropic の話題は最低1件。無ければ「各社の動き」に「Claude・Anthropic：大きな動きなし」と書く
7. **主要なAIツールの新機能は漏らさない**（Claude・Claude Code・ChatGPT・Codex・Gemini・Cursor・GitHub Copilot・Perplexity・NotebookLM・Midjourney など）。候補にある新機能は、10件に入れるか「その他の見出し」に入れるかのどちらかで必ず載せる。迷ったら10件のほうに入れる

## 5. 書く

### 全体分析

直近7日分の日次ページと「各社の動きメモ」を踏まえて書く。1日分の点ではなく流れとして書く。

- **全体の傾向**：2〜3点。今日のニュース同士のつながり、先週からの続き
- **各社の動き**：動きのあった会社ごとに1〜2行。資金調達・人事・提携はここで使う
- **あなたへの示唆**：今日試すとよいもの、注目しておくもの。2〜3点

### 1件の書き方

- **タイトル**：何が起きたかが一行でわかるように。印（【すぐ試せる】など）は付けない
- **要約**：2〜3文。何が・いつから・誰が使えるか。数字や条件は記事どおりに書く
- **🔰 つまり何ができる？（AIツールの新機能のときは必ず書く）**：2〜3文。機能の説明をなぞらず、かみ砕く
  - 「たとえば◯◯したいときに、こう使える」という具体的な使い道を1つ以上
  - 何が新しいのか・何がすごいのか（これまでとの違い）
  - 本人はAIツールの新機能を「使い道がわからない」「インパクトがつかめない」と感じやすい。そこを埋めるのがこの欄の役目
- **💡 あなたへの関係**：3つ、それぞれ1文で
  ①このニュースで、本人の何が変わるか（開発・仕事・発信・契約のどれに効くか）
  ②具体的な落とし込み：本人が作っているもの（Bubble のアプリ、サロン向けの文章作成・自動投稿、Claude Code の使い方、Nochon など）の場面に当てはめる
  ③今日やるなら何か（試す・設定を見直す・発信に使う・様子見する、のどれか）
- **リンク**：原文を1つ（一次情報を優先）、補足があれば1つ。表示名は「原文（Anthropic 公式）」「補足（The Verge）」のように、どこの記事かがわかるようにする

- 「あなたへの関係」は一般論で終わらせない。「便利になる」「比較材料になる」だけの文は不可。本人の具体的な場面か作業の名前を必ず出す
- 記事に書かれていないことを足さない。推測は「〜とみられる」と書き分ける
- 本文の転載はしない（要約と自分の言葉で書く）
- Slack の書式で書く：太字は `*…*`（行の頭から終わりまで）、リンクは `<URL|表示名>`。Markdown の `**…**` や `[文字](URL)` は使わない

### その他の見出し

10件に入らなかった候補のうち、知っておく価値のあるものを10〜20件。1行の見出しと一言の説明、リンク。
**AIツールの新機能で10件に入らなかったものは、ここに必ず全部入れる**（一言の説明は「何ができるか」を書く）。

## 6. Slack に投稿する

投稿はボット「AI News」から、カード型（Slack の Block Kit）で行う。カードの組み立てと投稿は `ai-news/post_digest.py` がやるので、あなたは中身を JSON に書くだけでよい。

1. 中身を JSON に書く（形は `ai-news/post_digest.py` の先頭の説明のとおり）。`python3` の `json.dump(..., ensure_ascii=False)` で `/tmp/digest.json` に保存する
   - `counts`：今日の10件の分野ごとの件数（例：「Claude 3 ・ 他社LLM 2 ・ エージェント 3 ・ 生成メディア 1 ・ 業界 1」）
   - `summary`：今日を一言で（1〜2文）
   - `items`：今日の10件（番号順）。`area` は「Claude・Anthropic／他社LLM／エージェント・MCP／生成メディア／業界・規制」から
   - `others`：その他の見出し
   - `feedback`：前回の反応から何を変えたかを1行
   - `notice`：Nochon に保存できなかったときなどの注意（無ければ省く）
2. まず組み立てだけ確かめる：`python3 ai-news/post_digest.py /tmp/digest.json --dry-run`
3. 投稿する：`python3 ai-news/post_digest.py /tmp/digest.json`
   - 親メッセージ（見出し・全体像・今日の10件・全体の傾向・各社の動き・あなたへの示唆）→ スレッドに10件のカード → 最後に「📋 その他の見出し」の順に投稿される
   - 出力の `parent_ts`（親メッセージの ts）を、手順 7 の Slack のリンクに使う
4. 前回の 🔍 が付いたニュースがあれば、そのニュースの古いスレッドに `🔍 解説` で始まる詳しい解説（背景・仕組み・使い方、5〜10行）を返信する（`curl` で `/api/agent/slack-post` に `{"text":"🔍 解説…","thread_ts":"…"}`）。新しい情報があれば今日のニュースにも入れる
5. **スクリプトが失敗したとき**（終了コード 1）：出力に、どこまで投稿できたかが出る。残りを `slack_send_message`（チャンネル `C0CF9HW549W`）で文字だけの形で投稿し、最後の報告に「ボットで投稿できなかった」と書く。一度失敗したら、その日は最後まで `slack_send_message` で投稿する（スレッドが混ざるため）
   - 文字だけの形：親は `📰 AIニュース …` で始め、各ニュースは `#番号 【分野】タイトル` で始める（翌朝の読み取りに使う）

## 7. Nochon に保存する

1. **その日のページ**：Slack に投稿した内容（親メッセージ＋全件）を Markdown で保存する。末尾に「Slack の投稿：<リンク>」を付ける

```bash
# {"page":"daily","date":"2026-11-04","content":"..."}
curl -sS -X PUT "https://personal-notes-khaki.vercel.app/api/agent/ai-news" \
  -H "Content-Type: application/json" --data-binary @/tmp/daily.json
```

2. **各社の動きメモ**（`page: "trends"`）：会社ごと・テーマごとの見出しの下に、今日の動きを1行ずつ足す（`- 11/4 …`）。3か月より古い行は、月ごとに1行の要約にまとめてから消す。長期の流れはここに残る
